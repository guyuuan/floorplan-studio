# 筑间 · Floorplan Studio

参考 [wy51ai/floorplan-3d](https://github.com/wy51ai/floorplan-3d) 的功能，使用 **Next.js + React + Three.js + TypeScript** 重新实现的本地户型设计工作台。

支持外部 Agent 通过标准 **MCP stdio** 读取户型图片、提交还原结果和调整设计。**不包含网页内置聊天助手**，无需在网页配置模型 API Key。图片理解由支持视觉的外部 Agent 完成。

## 启动

需要 Node.js 22 LTS 与 npm。

```sh
npm ci
npm run dev
```

浏览器打开 <http://127.0.0.1:3000>。若 3000 端口被占用，以终端实际输出的地址为准；网页「连接 Agent」会生成使用当前端口的配置。

生产模式：

```sh
npm run build
npm start
```

项目默认只监听 `127.0.0.1`。数据保存在项目目录的 `.data/`，不是浏览器缓存。项目几何、历史和原图由本地服务持久化；浏览器只记住最近打开的项目 ID。备份 `.data/` 或导出完整 JSON 即可保存方案。不要提交 `.data/`、`.env.local` 或凭据。

## 工作流程

1. 从项目菜单新建项目，上传 PNG、JPG 或 WebP 户型图片，最大 10 MB、4000 万像素。
2. 点击「连接 Agent」，把生成的配置添加到外部 MCP 客户端。保持网页服务运行。
3. 请支持看图的 Agent 列出项目、读取原图并提交还原的墙体、门窗与房间数据。没有可靠尺寸时应先询问用户，不能编造实际尺寸。
4. 在网页核对比例，确认现有尺寸准确，或用已知长度重新标定；逐墙纠正类型，再确认全部墙体。
5. 进入空间设计阶段。在外部 Agent 的对话中提出调整需求，也可在网页中手动操作。
6. 在 2D、3D、双视图间切换，导出当前视图 PNG 或完整方案 JSON。

首次可点击「探索一个示例空间」。`examples/sample-floorplan.png` 是合成的测试户型图片；`examples/sample-floorplan.json` 是对应的完整方案。示例不会自动替代用户上传的户型。

Agent 提示词示例：

> 列出筑间的项目，读取我刚上传的原始户型图片，还原外轮廓、墙体、门窗和房间。不能仅凭墙线粗细判断承重，无法确认的墙体标记为 unknown。尺寸不清楚时先问我，提交后等待我在网页核对。

> 读取当前项目，在保留外墙、外墙现有门窗和承重墙的前提下，优化客餐厅布置。先读取最新 revision，再批量提交操作。

## 墙体与门窗规则

| 类型               | 拆除 / 移动 / 改厚度     | 新增、移动或删除门窗   |
| ------------------ | ------------------------ | ---------------------- |
| 外墙               | 禁止                     | 禁止，现有外墙门窗固定 |
| 承重墙             | 禁止                     | 禁止                   |
| 已确认的非承重内墙 | 允许，支持按 mm 局部拆除 | 允许                   |
| 未确认的墙体       | 禁止                     | 禁止                   |

- 墙体类型只能由用户在网页手动纠正，MCP Agent 不能修改类别或确认结构。
- Agent 的全量还原仅在 `reconstruction` 阶段允许。确认进入 `design` 后，必须通过单项或批量设计命令编辑，不能覆盖完整模型。
- 新建墙体只能是非承重内墙，并且不能超出外轮廓。
- 局部拆除会保留剩余墙段、重新挂接保留门窗，并移除与拆除范围相交的内墙门窗。
- 洞口不可越过墙端、超出墙高或相互重叠。家具不可穿墙或超出建筑外轮廓。
- 2D、3D、网页操作和 MCP 使用同一个模型及同一套服务端校验。
- 批量命令原子执行，任何一项失败都不保存；`expectedRevision` 冲突返回 409，避免覆盖其他操作。
- JSON 导入建立一个新项目，保留原图和完整几何，重新进入墙体核对流程，不覆盖当前方案。

## 编辑功能

- 62 件家具素材，按房间分类与搜索；点击添加或拖入 2D 画布。
- 2D 家具拖动、贴墙吸附（按 Alt 暂停）、属性修改、旋转、复制和删除。
- 新建内墙、整段或局部拆除内墙、编辑端点和厚度、增删移动内墙门窗。
- 墙体变化后重新计算房间区域和面积，尽量保留房间名称及地面材质。
- 六种地面材质，材料估算包含 5% 损耗。
- 2D 测量、缩放和平移，尺寸、房间、家具、网格、承重墙及原图参考图层。
- Three.js 鸟瞰、俯视、房间聚焦，剖切墙 / 全高墙，日照与室内夜间照明。
- 3D 家具选择和拖动；门扇可点击开关。漫游支持 WASD、方向键和 E 开关附近的门。
- 撤销 / 重做和最近操作记录；外部 Agent 的操作约每 2 秒同步到网页。
- PNG 导出与完整 JSON 导入导出。双视图模式导出 2D PNG。

快捷键：`V` 选择、`H` 平移、`W` 新建墙、`D` 门洞、`O` 窗洞、`M` 测量、`T` 切换 2D/3D、`R` / `Shift+R` 旋转家具、`Delete` 删除、`F` 适应画布、`Ctrl/⌘+Z` 撤销、`Ctrl/⌘+Shift+Z` 重做。

## MCP 接入

推荐直接复制网页「连接 Agent」中的配置。也可以在项目目录生成配置：

```sh
node scripts/print-mcp-config.mjs
```

配置使用本机 Node、绝对脚本路径和数据目录，客户端不必从项目目录启动。默认认证凭据在 `.data/mcp-token` 自动生成；MCP 子进程从相同目录读取，不会输出到终端或配置。

| 工具                    | 用途                                               |
| ----------------------- | -------------------------------------------------- |
| `list_projects`         | 获取项目 ID、阶段与修订号                          |
| `create_project`        | 从 Base64 原图建立待还原项目；也可让用户在网页上传 |
| `get_source_image`      | 返回原始图片内容，供支持视觉的 Agent 查看          |
| `get_project`           | 读取完整当前模型、状态与 revision                  |
| `restore_floorplan`     | 仅在还原阶段提交结构化户型                         |
| `get_furniture_catalog` | 查询家具类型及默认尺寸                             |
| `apply_design_commands` | 原子批量编辑设计，服务端强制执行结构保护           |
| `export_project_json`   | 导出完整方案数据                                   |

资源 `floorplan://workflow` 描述还原、核对及设计工作流。MCP 的 Schema 会向客户端提供参数结构。所有坐标和尺寸单位均为 **mm**；墙体端点定义中心线，`boundary` 定义建筑外皮，不重复首点；洞口 `offset` 从墙体起点沿墙计算，3D 由同一模型生成。

## 代码结构

```text
src/app/                 Next.js 页面、样式与 HTTP 接口
src/components/          React 工作台、SVG 2D、Three.js 3D
src/domain/schema.ts     户型与操作的 Zod Schema
src/domain/engine.ts     墙体保护、状态机、批量操作与撤销
src/domain/geometry.ts   墙体几何、空间分区及面积计算
src/server/              本地持久化、原子写入、并发控制与来源校验
src/mcp/                 MCP 工具、资源与 stdio 入口
tests/                  规则、持久化、并发及往返测试
scripts/verify-mcp.ts    真实 MCP 客户端端到端验证
```

## 验证

```sh
npm test
npm run typecheck
npm run build
```

启动网页服务后，可运行真实 MCP 客户端集成验证：

```sh
node --import tsx scripts/verify-mcp.ts
```

脚本仅创建和清理自己的测试项目，验证工具发现、图片读取、还原提交、用户确认、结构保护、设计编辑、版本冲突、导出和鉴权。

## 当前适用范围

- 本版本面向**本机单用户**，提供 stdio MCP。网页 HTTP 接口没有多用户登录与租户隔离，不应直接暴露到公网；服务器部署需增加相应的身份认证和存储适配。
- 已验证工具和数据流程；实际图片的识别精度取决于外部 Agent 的视觉能力、图片清晰度和尺寸信息，需用真实户型验收。网页不会自行识别图片。
- 墙体模型支持任意方向的直墙、厚度和洞口，不支持弧墙、复杂梁柱或多楼层。家具使用程序化几何模型。
- 房间划分按完整墙线计算，门洞保留房间边界；拆除墙段后连通区域会合并。大开敞空间的功能分区仍可能需要进一步划分。
- 原图参考适应画布显示，未实现逐像素透视配准；原始图片可独立查看。测量线是当前画布的临时辅助线，保存方案时不持久化。
- 3D 漫游的碰撞检测覆盖边界、墙体和门洞，不包含家具；触屏支持拖动移动，尚未提供独立虚拟摇杆。
- 原项目的中英文切换和固定打印比例尚未移植。本轮保留的交付形式为 PNG 和 JSON。

若进程意外中断导致某个项目持续显示忙碌，请先停止全部项目服务，再仅删除 `.data/<该项目ID>.lock/` 后重启；不要删除对应 `.json` 或 `.image` 文件。
